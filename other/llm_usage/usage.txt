User prompt: In R, how can I use regex to extract the values of the latitude/longitude coordinates in a string like this? {"coordinates": [[-79.360567,
43.62612]], "type": "MultiPoint"}
Response: To extract coordinates using regex in R, you can match optional negative signs and floating-point numbers inside brackets. In GeoJSON
format, coordinates are ordered as [longitude, latitude].
Here are the best ways to do this, depending on your preferred package ecosystem:
Option 1: Base R (regmatches + gregexpr)
Base R uses Perl-compatible regular expressions (perl = TRUE) to match any sequence representing a signed decimal number (-?[0-9]+\.?[0-
9]*):
txt <- '{"coordinates": [[-79.360567, 43.62612]], "type": "MultiPoint"}'
# Pattern matching signed integers or decimals
pattern <- "-?\\d+\\.?\\d*"
# Extract all numeric values
matches <- regmatches(txt, gregexpr(pattern, txt, perl = TRUE))[[1]]
coords <- as.numeric(matches)
lon <- coords[1] # -79.360567
lat <- coords[2] # 43.62612
Option 2: Using stringr (stringr::str_match)
If you want to explicitly capture both values in one shot directly from the [[...]] block:
library(stringr)
pattern <- '\\[\\[\\s*(-?\\d+\\.\\d+)\\s*,\\s*(-?\\d+\\.\\d+)\\s*\\]\\]'
result <- str_match(txt, pattern)
lon <- as.numeric(result[, 2]) # -79.360567
lat <- as.numeric(result[, 3]) # 43.62612
\\[\\[ matches the opening double brackets.
(-?\\d+\\.\\d+) creates a capture group for negative or positive decimal numbers.
\\s*,\\s* matches the comma delimiter with any surrounding whitespace.
Alternative: Parse as JSON (Recommended)
Because your input is valid JSON/GeoJSON, parsing the string structurally is generally safer and less fragile than regex:
library(jsonlite)
data <- fromJSON(txt)
# Coordinates array: matrix or nested vector
coords <- data$coordinates[1, ]
lon <- coords[1] # -79.360567
lat <- coords[2] # 43.62612

Response: The error "Objects equal but not identical" means the numbers match, but their underlying data types (classes) differ.
In R:
1:233 generates a vector of type integer (typeof(1:233) is "integer").
readr::read_csv() reads whole numbers as standard floating-point doubles/numeric by default (typeof(cleaned_data$id) is "double").
expect_identical() requires both the values and the types to match perfectly, so comparing a double to an integer fails.
Solutions
Option 1: Use expect_equal() (Recommended)
expect_equal() checks for numerical equivalence and ignores minor type differences like double vs integer:
test_that("'id' is unique and in strictly increasing sequential order", {
 expect_equal(cleaned_data$id, 1:233)
})
Option 2: Keep expect_identical() and cast to integer
If you strictly want to enforce that both are integers:
test_that("'id' is unique and in strictly increasing sequential order", {
